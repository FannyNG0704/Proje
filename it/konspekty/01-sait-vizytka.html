1. Як браузер отримує сайт

Сайт — це файли (HTML, CSS, картинки), які лежать на чужому комп'ютері — сервері. Браузер просить ці файли і збирає з них сторінку.

sequenceDiagram
  participant B as Браузер
  participant D as DNS («телефонна книга»)
  participant S as Сервер (хостинг)
  B->>D: Яка IP-адреса у gldprof.es?
  D-->>B: 76.76.21.21
  B->>S: GET / (через HTTPS)
  S-->>B: 200 OK + index.html
  B->>S: GET style.css, foto.webp
  S-->>B: 200 OK + файли
  Note over B: Браузер збирає сторінку і показує
  • Домен (gldprof.es) — зручна для людей назва. Комп'ютери знають тільки IP-адреси (цифри).
  • DNS перекладає домен в IP — як контакти в телефоні: ти шукаєш «Брат», телефон набирає номер.
  • HTTP / HTTPS — мова, якою браузер і сервер розмовляють. «S» = secure: дані шифруються, ніхто посередині (наприклад, у публічному Wi-Fi) не прочитає і не підмінить.
  • 200 OK — «ось твій файл». 404 — «такого файлу немає». 500 — «на сервері щось зламалось».
  • index.html — файл, який сервер віддає, коли адреса не називає файл (просто gldprof.es). Тому головна сторінка завжди index.html.

Зараз твій сайт відкривається за адресою C:/Users/gladu/Gldprof/index.html — браузер бере файл прямо з диска (протокол file://), без сервера і DNS. Так зручно вчитися, але цю адресу ніхто, крім тебе, не відкриє. В інтернет сайт піде в задачі 7.

2. Контент → структура → вигляд

Професійний порядок роботи над сайтом:

  1. Контент — що сказати і кому. Це твоя анкета: хто ми, послуги, ціни, райони, як працюємо. Задача 1.
  2. Структура (HTML) — з яких блоків складається сторінка і в якому порядку. Задача 2.
  3. Вигляд (CSS) — кольори, шрифти, розміщення, анімації. Задача 3.
  4. Поведінка (JavaScript) — те, що реагує на дії: слайдер, калькулятор. Частково P1, далі P2.
Аналогія з будівництваКонтент — проєкт і кошторис. HTML — каркас і стіни. CSS — штукатурка, плитка, фарба. JavaScript — електрика: вимикачі, які щось роблять. Ніхто не кладе плитку, поки не стоять стіни.
Підводний каміньНовачки починають з кольорів і шрифтів, тиждень «малюють», а потім виявляється, що немає тексту, блоки не в тому порядку — і все переробляється. Дизайн без контенту — це плитка без стін.

Рішення по контенту, які ми прийняли

  • Сайт подає компанію, не двох людей: «nosotros», «el equipo». Компанія може рости.
  • Основний обсяг робіт (~80% замовлень), без списку «чого не робимо». Для решти — фраза в тоні компанії: «Coordinamos la obra completa…».
  • Мова — іспанська (клієнти — іспанці). Інші мови — пізніше.
  • Ціни — «desde …», точна після огляду; дві колонки: тільки робота / з матеріалом.
  • Сайт не публікуємо, поки немає autónomo (закон вимагає ім'я і NIF у «Aviso legal»).

3. HTML: теги, атрибути, вкладеність

HTML (HyperText Markup Language) — мова розмітки, не програмування. Вона нічого не обчислює, а лише каже браузеру: «це заголовок», «це меню», «це посилання».

<a href="#contacto">Contacto</a>
 │  └── атрибут ──┘ └ вміст ┘ └ закриваючий тег
 └ відкриваючий тег
  • Тег — слово в кутових дужках: <h1>. Більшість тегів парні: відкриваючий <h1> і закриваючий </h1> зі скісною рискою.
  • Елемент — тег разом із вмістом: <h1>Reformas…</h1>.
  • Атрибут — додаткове налаштування всередині відкриваючого тегу: назва="значення". Наприклад, href у посиланні, id у секції, lang у html.
  • Порожні (void) теги — без закриваючої пари, бо всередині нічого не буває: <meta>, <img>, <br>, <input>.

Вкладеність = дерево

Елементи лежать один в одному, як коробки в коробках. Браузер будує з них дерево — DOM (Document Object Model). Ось дерево твоєї сторінки:

flowchart TD
  html --> head
  html --> body
  head --> meta1[meta charset]
  head --> meta2[meta viewport]
  head --> title
  body --> header
  body --> main
  body --> footer
  header --> a1[a · Gldprof]
  header --> nav
  nav --> a2[a · Servicios]
  nav --> a3[a · Cómo trabajamos]
  nav --> a4[a · Contacto]
  main --> s0[section · h1 + p]
  main --> s1[section#servicios]
  main --> s2[section#como-trabajamos]
  main --> s3[section#contacto]

Правило: що відкрив останнім — закриваєш першим. <nav><a>…</a></nav> — правильно; <nav><a>…</nav></a> — коробки перехрещені, браузер вгадуватиме, і часто вгадує не те.

Підводні камені (усі — з нашого заняття)
  • Забутий закриваючий тег (<header> без </header>) — браузер вважає шапкою все до кінця сторінки. Помилки на екрані не буде — буде «дивна» верстка пізніше.
  • Слово без дужок — це текст, не тег. main footer або p: Trabajo… браузер просто покаже як слова.
  • Круглі дужки (main) — не тег. Тільки кутові < >.
  • Шаблон з підказки — не код. У <a href="адреса">текст</a> слова «адреса» і «текст» — місця, куди підставляєш своє.

Коди мов

У lang пишуть стандартний двобуквений код мови (ISO 639-1): es — іспанська, uk — українська, en — англійська, ru — російська. Можна уточнити країну: es-ES.

Підводний каміньУкраїнська — uk, а не ua. UA — код країни (домен .ua), а не мови. Так само en — мова, а GB/US — країни.

Title: як писати

Схема: назва · що робимо · місто, до ~60 символів (довше Google обрізає «…»). Ключові слова — ті, що люди вводять у пошук: «reformas Málaga». У кожної сторінки сайту — свій title.

  • Google розуміє, де головний вміст, а де меню і низ, — і краще ранжує.

6. Заголовки і текст

  • <h1>…<h6> — заголовки за важливістю, як зміст книги. h1 — назва книги, h2 — розділи, h3 — підрозділи.
  • Один h1 на сторінку — головна тема. У нас: «Reformas y acabados en Málaga».
  • Не перестрибувати рівні: після h2 — h3, не h5.
  • <p> — абзац. <ul> + <li> — список з крапками (unordered list / list item), <ol> — нумерований.
  • <strong> — важливе (жирне), <em> — наголос (курсив).
Підводний каміньВибирати заголовок «за розміром» («хочу великий текст — поставлю h1»). Розмір — справа CSS. Тег — це значення. Інакше в Google у тебе п'ять «головних тем».

Як працює стрибок по меню

<a href="#servicios">Servicios</a>      ← у меню: з решіточкою
…
<section id="servicios">…</section>   ← у розділі: без решіточки

id — унікальне «ім'я» елемента. Браузер шукає елемент з таким id і прокручує до нього; адреса в рядку браузера стає …/index.html#servicios — таким посиланням можна поділитися, і воно відкриється одразу на потрібному розділі.

Правила для id (і для назв файлів)
  • Унікальний: два однакові id на сторінці — помилка.
  • Маленькі латинські літери, цифри, дефіс: como-trabajamos. Без пробілів і без ó, ñ.
  • Якщо id в меню і в розділі відрізняються хоч на літеру (servicio ≠ servicios) — посилання мовчки не працює. Ніякої помилки.
  • Великі й малі літери — різні: Servicios ≠ servicios. На сервері (Linux) так само з назвами файлів: Foto.jpg ≠ foto.jpg, а Windows різниці не бачить — тому «у мене працює, а в інтернеті — ні».

8. Чому сторінка «сира» і синя

У кожного браузера є стилі за замовчуванням (user agent stylesheet): посилання — сині й підкреслені, h1 — великий і жирний, шрифт — Times New Roman, відступи — стандартні. Тому сторінка без CSS виглядає як документ 1995 року. Це норма, і саме так перевіряється задача 2: якщо без жодного стилю все читається зверху вниз у правильному порядку — структура правильна.

Ще одна особливість: браузер ігнорує зайві пробіли, переноси і порожні рядки в коді (whitespace collapsing). Порожній рядок у HTML ≠ порожній рядок на сайті. Відступи на сторінці робить CSS.

10. AI-підказки: чому вимкнули

Copilot у VS Code пропонував код сірим текстом і зеленими блоками («Next Edit Suggestions»), а Tab їх приймав. Один раз він вставив цілу сторінку — з фразою «Reformas integrales», яку ми свідомо не пишемо (для іспанця це «все під ключ, включно з сантехнікою»). Ось головний урок:

Логічний ланцюжокAI пише код швидко → але він не знає твоїх рішень і контексту → код треба читати і розуміти перед тим, як прийняти → а читати вміє тільки той, хто писав сам. Тому основа — руками; AI — пізніше, як інструмент, за яким ти перевіряєш.

Вимкнули в налаштуваннях вкладки Workspace (тільки для папки Gldprof): «Chat: Disable AI Features». Emmet і автозакриття тегів — не AI, вони залишились.

11. Git для проєкту

git init                                   ← папка стає репозиторієм (один раз)
git add .                                  ← покласти всі зміни «в коробку»
git commit -m "Каркас сторінки HTML"       ← запечатати коробку з підписом
git log --oneline                          ← історія комітів
  • Один проєкт = одна папка = один репозиторій. Тому Gldprof поруч із kursy, а не всередині: сайт піде в інтернет окремо, і навчальні файли (README курсу, .env) туди потрапити не повинні.
  • Коміт — точка збереження, як у грі. Правило: зробив робочий шматок → коміт. Зламав щось завтра — повернешся.
  • root-commit — найперший коміт. HEAD -> main — ти зараз на гілці main, на останньому коміті.
  • Зараз історія тільки на твоєму комп'ютері. На GitHub ми її ще не відправляли — це буде в задачі 7, бо хостинг бере сайт саме з GitHub.

12. Відповіді на питання самоперевірки

Чому посилання «Servicios» знаходить свій розділ?

Бо href="#servicios" у меню і id="servicios" у секції збігаються літера в літеру. # означає «на цій сторінці, елемент з таким id». Не збігаються — посилання мовчки нічого не робить.

Що буде без <meta name="viewport">?

На комп'ютері — нічого не зміниться. На телефоні браузер вдаватиме, що екран шириною ~980px, і зменшить усю сторінку: дрібний текст, треба розтягувати пальцями, і жодні стилі «для телефона» (задача 3) не спрацюють. А з телефонів приходить 70%+ відвідувачів.

Що відбувається між введенням адреси і появою сторінки?

DNS перекладає домен в IP → браузер встановлює захищене з'єднання (HTTPS) з сервером → просить index.html → читає його, бачить посилання на CSS, картинки, шрифти — просить їх → будує дерево (DOM), застосовує стилі, малює. Див. схему в розділі 1.

Чому mobile-first, а не навпаки?

Більшість клієнтів шукають «reformas cerca de mí» з телефона. Простіше почати з вузького екрана (одна колонка) і додавати розкладку для ширших, ніж робити складний десктоп і потім «втискати» його в телефон. Детальніше — розділ 16.

Замовник хоче Google Analytics. Що сказати про закон?

В Іспанії/ЄС аналітика ставить cookies, що не є «технічно необхідними» → за LSSI (ст. 22.2) і RGPD потрібна попередня згода: банер, де «Rechazar» так само помітна, як «Aceptar», і скрипт не запускається до згоди. Плюс сторінка «Política de cookies». Альтернатива — аналітика без cookies (Plausible, Cloudflare Web Analytics) — тоді банер часто не потрібен. Розділ 22.

14. CSS: основи (задача 3)

CSS (Cascading Style Sheets) — «таблиці стилів»: правила, як виглядають елементи. Пишуться в окремому файлі style.css і підключаються в <head>:

<link rel="stylesheet" href="style.css">

Будова правила

h1 {                 ← селектор: КОГО стилізуємо
    color: #1d2430;  ← властивість: значення;
    font-size: 2rem;
}
СелекторКого вибираєПриклад

.cardУсі з class="card"картки послуг — основний інструмент
#contactoОдин елемент з idкраще не стилізувати через id (див. нижче)
nav aПосилання всередині navпункти меню

class — як «тип» (може бути в багатьох елементів, і в елемента може бути кілька класів). id — як «паспорт» (один на сторінку; для посилань і JavaScript).

Каскад, специфічність, успадкування

  • Каскад: якщо два правила кажуть різне, перемагає те, що нижче у файлі…
  • …якщо в них однакова специфічність («вага» селектора): id > class > тег. Правило з #contacto переб'є .card, навіть якщо стоїть вище. Тому стилі через id потім важко перебити.
  • Успадкування: колір і шрифт, задані для body, переходять усім усередині. Відступи і рамки — не переходять.

15. Box model, Flexbox, Grid

Кожен елемент — коробка

flowchart LR
  subgraph M[margin — зовнішній відступ]
    subgraph B[border — рамка]
      subgraph P[padding — внутрішній відступ]
        C[content — вміст]
      end
    end
  end
  • content — текст/картинка; padding — «повітря» всередині рамки; border — рамка; margin — відстань до сусідів.
  • box-sizing: border-box — щоб width: 300px означало «разом з padding і рамкою». Ставлять для всього на початку файлу. Без цього блоки «вилазять» за ширину.
  • Блокові елементи (section, p, h1) займають усю ширину і стають один під одним. Рядкові (a, strong) стоять у рядку з текстом.
АналогіяПлитка на стіні: плитка — content, padding — це якби в самої плитки був бортик, border — край плитки, margin — шов між плитками.

Flexbox — розкласти в ряд або в стовпчик

nav { display: flex; gap: 1rem; }        ← пункти меню в ряд з проміжком
header { display: flex; justify-content: space-between; align-items: center; }
                                         ← логотип зліва, меню справа, по центру висоти

Grid — сітка з рядів і колонок

.servicios { display: grid; grid-template-columns: repeat(auto-fit, minmax(260px, 1fr)); gap: 1rem; }
          ← картки послуг: скільки влізе колонок по ≥260px; на телефоні — одна

Правило вибору: одна лінія (меню, кнопки в ряд) — Flexbox; дві осі (картки сіткою, галерея) — Grid.

Підводний каміньРозставляти блоки відступами margin «на око» і фіксованими пікселями. На іншому екрані все з'їжджає. Відстані між сусідами — gap у flex/grid.

16. Адаптив і mobile-first

Responsive (адаптивний) — один сайт, що добре виглядає на будь-якому екрані. Mobile-first — спочатку пишемо стилі для телефона, потім додаємо для ширших через media queries:

/* базові стилі — телефон (від 360px) */
.servicios { display: grid; gap: 1rem; }

/* планшет і ширше */
@media (min-width: 768px) {
    .servicios { grid-template-columns: 1fr 1fr; }
}

/* комп'ютер */
@media (min-width: 1024px) {
    .servicios { grid-template-columns: repeat(3, 1fr); }
}

Ширини для перевірки: 360 (телефон), 768 (планшет), 1024–1440 (ноутбук і монітор).

DevTools — твій головний інструмент у задачі 3

  • F12 у браузері (або права кнопка → «Inspeccionar») — інструменти розробника.
  • Кнопка 📱 (Ctrl+Shift+M) — режим пристрою: вибираєш ширину екрана.
  • Клікаєш на елемент — бачиш, які CSS-правила на нього діють і чому якесь перекреслене (переможене каскадом).
  • Можна міняти CSS прямо там і бачити результат — але це не зберігається. Знайшов значення → переписав у style.css.
Підводні камені
  • Перевіряти тільки в режимі пристрою DevTools. Обов'язково відкрий на справжньому телефоні.
  • Горизонтальна прокрутка на телефоні — майже завжди якийсь блок або картинка ширші за екран. Ліки: max-width: 100% для картинок.
  • Кнопки і посилання менші за ~44×44px — пальцем не влучити.

19. Форма заявки (задача 6)

<form action="https://formspree.io/f/xxxx" method="POST">
    <label for="nombre">Nombre</label>
    <input id="nombre" name="nombre" required>

    <label for="tel">Teléfono</label>
    <input id="tel" name="telefono" type="tel" required>

    <label for="msg">¿Qué necesita?</label>
    <textarea id="msg" name="mensaje"></textarea>

    <button type="submit">Pedir presupuesto</button>
</form>
  • label + for/id — підпис, прив'язаний до поля: клік по підпису ставить курсор у поле, і screen reader знає, що це за поле. Placeholder не замінює label.
  • name — під якою назвою значення прийде тобі в листі. Без name поле не відправиться.
  • type — tel відкриває на телефоні цифрову клавіатуру, email перевіряє @.
  • Куди йдуть дані? У простого сайту (тільки HTML/CSS) немає сервера, який прийме форму. Тому — сервіс форм: Formspree або Netlify Forms. Він приймає заявку і пересилає тобі на пошту. Свій сервер — P6.
Підводні камені
  • Спам. Боти знаходять форми за години. Захист: honeypot (приховане поле, яке заповнює тільки бот), reCAPTCHA/Turnstile, обмеження в сервісі форм.
  • Email відкритим текстом на сторінці — боти зберуть і засиплють спамом. Краще форма + WhatsApp-кнопка.
  • RGPD: форма збирає персональні дані → поруч коротка інформація (хто відповідальний, навіщо, скільки зберігаємо, права) + посилання на «Política de privacidad» + чекбокс згоди без заздалегідь поставленої галочки.
  • Сервіс форм зберігає заявки на своїх серверах (часто в США) — це теж треба вказати в Política de privacidad.

21. Перевірка якості (задача 8)

  • Lighthouse — вбудований у Chrome (F12 → вкладка Lighthouse). Ставить оцінки 0–100: Performance (швидкість), Accessibility (доступність), Best Practices, SEO. Мета — ≥ 90 усюди, і для телефона, і для ПК.
  • Пройти сайт клавіатурою: тільки Tab / Shift+Tab / Enter. Кожне посилання і поле мають бути досяжні, а фокус — видно (рамка навколо). Хто не може користуватися мишкою, користується саме так.
  • Контраст тексту і фону — не менше 4.5:1 (стандарт WCAG). Сірий текст на білому часто не проходить. Перевірка: WebAIM Contrast Checker.
  • Валідатор W3C — знаходить незакриті теги і помилки HTML.
  • Справжній телефон — і повільний інтернет (DevTools → Network → «Slow 4G»).
