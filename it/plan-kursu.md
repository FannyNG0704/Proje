# Курс IT: від бази до «знаю, де підводні камені»

## Ідея курсу

Мета не «вивчити мову програмування», а **розуміти, як влаштовані реальні продукти** і
**заздалегідь бачити, де вони ламаються**. Тому кожен модуль має однакову структуру:

1. **Що це і навіщо** — суть простими словами.
2. **Як це працює всередині** — щоб не було «магії».
3. **Підводні камені** — що ламається в реальних проєктах.
4. **Практика** — маленьке завдання, бажано прив'язане до нашої апки з Фані.
5. **Самоперевірка** — 3–5 питань. Модуль пройдено, коли можу відповісти своїми словами.

> Припущення: апка з Фані — веб/мобільна, з сервером і базою даних. Стек (мова, фреймворк)
> уточнимо на першому занятті — від нього залежать приклади, але не самі принципи.

---

## Три рівні: що я можу робити сам

| Рівень | Що можу зробити сам | Каменів | Модулі |
|---|---|---|---|
| **1. Сам, спокійно** | Лендинг / сайт-візитка, todo-список, калькулятор, простий бот, скрипт для автоматизації | Мало | 0–4 |
| **2. Сам, але з чек-листом** | Апка з логіном, базою даних, адмінкою (CRUD), завантаженням файлів, деплоєм | Середньо: безпека, дані, деплой | 5–9 |
| **3. Тільки з чек-листом + чужим рев'ю** | Гроші / підписки, реальний час, персональні дані багатьох людей, високе навантаження | Багато, і помилка дорого коштує | 10–13 |

**Правило:** беручи чужу роботу рівня 3 — спочатку пройти [карту ризиків](karta-ryzykiv.md) і
чесно сказати замовнику, що буде займати час (безпека, тести, моніторинг), а не тільки «екранчики».

## Блок A. Фундамент (рівень 1)

### Модуль 0. Інструменти і як працювати
- Термінал: `cd`, `ls`, `mkdir`, шляхи, змінні середовища.
- **Git**: commit, branch, merge, push/pull, конфлікти, `.gitignore`. Що таке pull request.
- Редактор (VS Code), дебагер, як читати помилку (stack trace) і гуглити її.
- Як вчитися з AI (Claude) так, щоб вчитися, а не копіювати.
- **Камені:** закомітити пароль/ключ у git (він там назавжди, навіть після видалення);
  працювати одразу в `main`; не читати текст помилки до кінця.

### Модуль 1. Як працює інтернет і веб
- Клієнт ↔ сервер. DNS, IP, порт, домен.
- **HTTP**: метод (GET/POST/PUT/DELETE), URL, заголовки, тіло, статус-коди (200, 301, 400, 401, 403, 404, 500).
- HTTPS і сертифікати — що саме шифрується.
- Cookies, сесії, localStorage. CORS — чому браузер «блокує» запит.
- **Камені:** плутати 401 і 403; думати, що CORS — це захист сервера (ні, це захист браузера);
  довіряти всьому, що прийшло від клієнта.

### Модуль 2. Програмування: база (на мові нашого стеку, скоріш за все JavaScript/TypeScript)
- Змінні, типи, умови, цикли, функції, масиви/об'єкти.
- Помилки і `try/catch`. **Асинхронність**: callback → Promise → `async/await`.
- TypeScript: навіщо типи.
- **Камені:** `==` vs `===`; забутий `await`; дробові числа (`0.1 + 0.2 !== 0.3` — тому гроші
  зберігають у центах цілим числом); дати і часові пояси.

### Модуль 3. Frontend
- HTML (структура), CSS (вигляд, flex/grid, адаптив під телефон), JS у браузері.
- Компонентний фреймворк (React або той, що в апці): стан, props, ефекти.
- Форми і валідація на клієнті.
- **Камені:** валідація тільки на фронті (обходиться за 10 секунд); секретні ключі у фронтенд-коді
  (їх бачить кожен); не тестувати на телефоні; доступність (accessibility).

### Модуль 4. Backend і API
- Що таке API, REST, JSON. Маршрути, контролери, middleware.
- Валідація вхідних даних **на сервері**. Обробка помилок. Логи.
- Конфіг через змінні середовища (`.env`).
- **Камені:** віддавати користувачу текст внутрішньої помилки (stack trace);
  відсутність ліміту запитів; немає пагінації — один запит тягне 100 000 рядків.

**🎯 Практика блоку A:** невеликий проєкт «з нуля сам» — наприклад, todo-апка з фронтом і API (поки без логіну).

## Блок B. Справжня апка (рівень 2)

### Модуль 5. Бази даних
- SQL (PostgreSQL) vs NoSQL (MongoDB, Firebase) — коли що.
- Таблиці, ключі, зв'язки, індекси, транзакції, міграції.
- ORM (Prisma/Sequelize тощо) — що він робить за тебе.
- **Камені:** SQL injection; немає індексу → все повільно на реальних даних; N+1 запити;
  зміна схеми без міграції; **немає бекапів** (і ніхто не перевіряв, що бекап відновлюється).

### Модуль 6. Автентифікація і авторизація
- Автентифікація = хто ти. Авторизація = що тобі можна.
- Паролі: тільки хеш (bcrypt/argon2), ніколи не відкритим текстом.
- Сесії vs JWT. OAuth («Увійти через Google/Apple»). 2FA. Скидання пароля.
- **Камені:** перевірка «чи залогінений», але не «чи це ЙОГО запис» (IDOR — найчастіша дірка:
  міняєш `/orders/15` на `/orders/16` і бачиш чуже); JWT без терміну дії; посилання для
  скидання пароля, яке не згорає.

### Модуль 7. Безпека (OWASP Top 10)
- Головні атаки: injection, XSS, CSRF, IDOR/broken access control, SSRF, слабкі паролі, вразливі залежності.
- Секрети: де зберігати ключі; ротація ключів.
- Rate limiting, захист від перебору паролів, капча.
- **Камені:** «у нас маленький проєкт, нас ніхто не буде ламати» — боти сканують усе автоматично;
  старі бібліотеки з відомими вразливостями.

### Модуль 8. Файли, email, сторонні сервіси
- Завантаження файлів (S3/Cloud Storage), розмір, тип, віруси.
- Відправка email/SMS/push. Інтеграції з чужими API.
- **Камені:** приймати будь-який файл (SVG/HTML з кодом); чужий API впав → впала вся апка
  (потрібні таймаути і повтори); перевищення лімітів платного API → великий рахунок.

### Модуль 9. Деплой і DevOps
- Хостинг (Vercel, Render, Railway, VPS, Firebase), домен, HTTPS.
- Середовища: dev / staging / production. Docker — що це.
- CI/CD (GitHub Actions): тести і деплой автоматично.
- Логи, моніторинг, алерти (Sentry тощо). Бекапи.
- **Камені:** тестувати на продакшн-базі; деплой у п'ятницю ввечері без можливості відкату;
  дізнатися про падіння від клієнтів, а не від алерту.

**🎯 Практика блоку B:** розібрати нашу апку з Фані по чек-листу модулів 5–9 і знайти, що там не так.

## Блок C. Складні системи (рівень 3)

### Модуль 10. Гроші: платежі і підписки
- Як працює оплата карткою; Stripe / платіжні провайдери; ніколи не зберігати номер картки самому (PCI DSS).
- Підписки: пробний період, продовження, невдала оплата, скасування, повернення коштів.
- **Вебхуки**: провайдер повідомляє сервер про оплату — перевірка підпису, повторні доставки.
- **Ідемпотентність**: одна оплата не має зарахуватись двічі.
- In-app покупки в App Store / Google Play — свої правила і комісія.
- Податки: IVA (ПДВ) в Іспанії/ЄС, рахунки-фактури.
- **Камені:** давати доступ за «success» з фронтенду замість підтвердження з вебхука;
  не обробити «оплата не пройшла»; гонки (два запити одночасно); шахрайство і chargebacks.

### Модуль 11. Реальний час і навантаження
- Polling vs WebSockets vs Server-Sent Events. Push-сповіщення.
- Перепідключення, втрата повідомлень, порядок повідомлень.
- Масштабування: кілька серверів, Redis pub/sub, черги (queue), фонові задачі.
- Кеш, CDN, балансувальник навантаження.
- **Камені:** WebSocket-з'єднання тримаються на одному сервері — при двох серверах повідомлення
  «губляться»; немає heartbeat → «мертві» з'єднання; один повільний клієнт гальмує всіх
  (backpressure); сервер падає без автоперезапуску.

### Модуль 12. Персональні дані і закон (ЄС / Іспанія)
- **GDPR (RGPD)** + іспанський закон **LOPDGDD**, регулятор — **AEPD**.
- Згода, політика конфіденційності, банер cookies, право на видалення даних, витік даних (72 год на повідомлення).
- **Камені:** збирати більше даних, ніж треба; аналітика/трекінг без згоди; сервери з даними поза ЄС без правової основи.

### Модуль 13. Якість: тести, архітектура, рев'ю
- Unit / integration / e2e тести. Що тестувати насамперед (гроші, доступ, критичні сценарії).
- Архітектура: розділення відповідальностей, моноліт vs мікросервіси (і чому на старті — моноліт).
- Code review: що дивитись.
- **Камені:** 100% покриття «для галочки»; передчасне ускладнення архітектури.

## Блок D. Робота з чужим проєктом (наскрізний)

### Модуль 14. Як брати проєкт / роботу
- Як читати чужий код: з чого почати (README, точки входу, структура, залежності).
- Як оцінювати задачу: що питати у замовника до початку (див. [карту ризиків](karta-ryzykiv.md)).
- Оцінка часу і чому вона завжди більша, ніж здається.
- **Камені:** погодитись на «просту апку з оплатою за тиждень»; не уточнити, хто відповідає
  за сервери, дані і юридичні питання.

## Порядок і темп

- Рекомендований темп: 1 модуль ≈ 1–2 тижні при 3–5 заняттях по 1 годині.
- Модулі 0–1 — швидко, якщо діагностика покаже, що знаю.
- Після кожного блоку — **підсумкова перевірка**: розібрати реальний кейс і назвати всі камені.
- Наскрізно: кожну нову тему примірюємо на апку з Фані («а як це в нас?»).
