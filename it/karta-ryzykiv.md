# Карта ризиків: «якщо в проєкті є X → обов'язково думай про Y»

Це шпаргалка для моменту, коли беру проєкт або нову задачу. Пройтися по кожному рядку
і чесно відповісти: «є це в проєкті?». Якщо так — праворуч те, що **обов'язково** закласти в роботу і в час.

## Базове (є майже завжди)

| Якщо є… | Логіка | Обов'язково думати про |
|---|---|---|
| **Будь-який сервер в інтернеті** | Боти сканують усе автоматично | HTTPS, оновлення залежностей, секрети не в коді, rate limiting, логи |
| **Форми / будь-яке введення від користувача** | Користувач може надіслати що завгодно | Валідація на сервері, захист від injection і XSS, ліміти розміру |
| **Логін / акаунти** | Будуть перебирати паролі і лізти в чужі акаунти | Хеш паролів, ліміт спроб, перевірка «це твій запис?» (IDOR), скидання пароля, 2FA для адмінів |
| **База даних** | Дані — найцінніше, і їх можна втратити | Бекапи + перевірка відновлення, міграції, індекси, доступ до БД не з інтернету |
| **Продакшн** | Все колись падає | Моніторинг і алерти, можливість відкату, окреме тестове середовище |

## Підвищений ризик

| Якщо є… | Логіка | Обов'язково думати про |
|---|---|---|
| **Гроші / оплата / підписка** | Де гроші — там будуть спроби їх вкрасти або отримати безкоштовно | Платіжний провайдер (не зберігати картки), підтвердження оплати **тільки** через вебхук з перевіркою підпису, ідемпотентність, невдалі оплати і скасування, повернення коштів, шахрайство, податки (IVA), тести саме на гроші |
| **Дані в реальному часі (чат, трекінг, ставки, котирування)** | З'єднання рвуться, сервер перевантажується, повідомлення губляться | WebSockets/SSE, перепідключення, heartbeat, порядок і дублікати повідомлень, масштабування (Redis/черги), автоперезапуск сервера, навантажувальні тести |
| **Персональні дані (ім'я, телефон, адреса, фото)** | ЄС: GDPR, Іспанія: LOPDGDD, штрафи від AEPD | Мінімум даних, згода, політика конфіденційності, cookies-банер, видалення акаунта, шифрування, план на випадок витоку |
| **Особливо чутливі дані (здоров'я, діти, документи, геолокація)** | Витік = реальна шкода людям + найбільші штрафи | Все з рядка вище + суворий доступ, журнал хто що дивився, юридична консультація |
| **Завантаження файлів** | Файл може бути шкідливим або величезним | Ліміт розміру і типу, окреме сховище, не віддавати як HTML, перевірка на віруси |
| **Сторонні API (карти, AI, SMS, email)** | Вони падають, змінюються і коштують гроші | Таймаути, повтори, запасний сценарій, ліміти витрат, ключі тільки на сервері |
| **Мобільна апка в App Store / Google Play** | Правила магазинів і довга перевірка | Рев'ю магазину (дні), правила in-app покупок і комісія, оновлення не миттєві → сервер має підтримувати старі версії апки |
| **Адмін-панель** | Один зламаний адмін = зламано все | 2FA, окремі ролі, журнал дій, не відкривати всім в інтернеті |
| **Багато користувачів / високе навантаження** | Те, що працює на 10 людях, падає на 10 000 | Кеш, індекси, пагінація, черги для важких задач, CDN, горизонтальне масштабування |
| **Розсилки email/SMS/push** | Спам-фільтри і скарги | Відписка, ліміти, підтвердження email (SPF/DKIM), згода на маркетинг |
| **Кілька мов / країн** | Формати і закони різні | Переклади, часові пояси, валюта, формати дат і чисел, місцеві закони |

## Питання до замовника перед стартом

1. Що буде через рік: скільки користувачів, які дані, чи будуть гроші?
2. Хто платить за сервери і сторонні сервіси? Хто власник акаунтів (домен, хостинг, Stripe)?
3. Хто відповідає за юридичну частину (політика конфіденційності, умови)?
4. Що буде, якщо сервіс впаде на годину? На день? (Від цього залежить, скільки вкладати в надійність.)
5. Хто підтримує проєкт після здачі?

> Будемо доповнювати цю карту після кожного модуля.
