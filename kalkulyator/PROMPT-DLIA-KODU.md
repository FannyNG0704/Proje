# Промпт для майбутньої сесії: написати ядро калькулятора

> Скопіюй усе нижче в нову розмову з Claude разом із папкою `kalkulyator/`. Рекомендована глибина: **high**.

---

Ти пишеш **ядро будівельного калькулятора** — чисту логіку без інтерфейсу. Головне — **точність розрахунків**; функції й дизайн — потім.

**Прочитай по черзі, перед тим як писати код:**
1. `BAZA.md` — головний документ: шари 0–5, порядок, структура папок, золоті приклади B1–B5.
2. `logika-02-struktura.md` — блоки позиції, помічники виміру, приклади S1–S13.
3. `logika-01-zemlia.md` — позиція, ділянки (tramos), техніка, податки, Європа, приклади G1–G12.
4. `SPEC.md` — загальна мета (матеріали, технології, табель) — **на майбутнє**, зараз не реалізовувати.

**Технічні правила (не порушувати):**
- JavaScript, ES modules, JSDoc-типи. Без зовнішніх бібліотек. Тести — вбудований `node:test` + `node:assert/strict`, запуск `node --test`.
- Чисті функції: вхід-об'єкт → результат-об'єкт. Без DOM, без глобального стану, без `Date.now()` всередині розрахунків.
- Гроші — цілі центи; ціни за одиницю — цілі десятитисячні евро. Округлення «половина вгору» тільки там, де вказано в BAZA (0.2). Кількості не округлювати.
- Кожна функція повертає `{ valor, explicacion }` або кидає помилку з людським текстом (українською; ключ помилки — латиницею для перекладу).
- Ручна правка (0.4) підтримується на рівні кількості, ціни, рядків «Додатково».
- Структура папок — точно як у BAZA «Як це лягає на код». Залежності тільки вниз: `volumen → superficie → lineal`; `geometria` не знає про `precio` і `resumen`.

**Порядок роботи (кожен крок закінчується зеленими тестами і комітом):**
1. Спершу перенеси **всі золоті приклади** (G, S, B) у `tests/golden.test.js` — тести мають **падати** (коду ще немає).
2. Шар 0 → 1 → 2 → 3 → 4A → 4B → 4C → 5. Для кожного: тести модуля → код → `node --test` зелений → коміт.
3. Незалежна перевірка: перерахуй кожен золотий приклад окремо (інший спосіб або окремий агент), щоб помилка в прикладі не стала «правильною» в коді.
4. Граничні випадки на кожен модуль: 0, від'ємні, дуже великі числа, см/мм, віднімання більше за додавання, % = −100, порожні списки.

**Якщо специфікація суперечлива або неповна:** не вигадуй мовчки. Запиши питання в `PITANNIA.md`, вибери найбезпечніший варіант, познач його в коді коментарем `// SPEC?` і скажи Назару.

**Готово, коли:** усі золоті приклади зелені; кожен модуль має свої тести; `explicacion` читається людиною; помилки — людською мовою; README з прикладом виклику для m², m³ і одної суми.

**Не робити зараз:** інтерфейс, збереження, акаунти, каталог робіт (плитка, пладур…), матеріали, табель (тільки якщо Назар попросить окремо).

Спілкуйся з Назаром українською, коротко, з готовими командами; терміни — англійською з поясненням.
